# SEO and LLM Publishing Runbook

Last verified: September 17, 2026

## Public discovery surfaces

- WordPress page and post HTML
- Canonical tags
- Titles and meta descriptions
- OpenGraph and social metadata
- JSON-LD schema
- `robots.txt`
- Sitemap index and child sitemaps
- Redirects
- Markdown page variants such as `/austin.md`
- `llms.txt`
- `llms-full.txt`
- Alpha Answers index and detail content

## Ownership before editing

Determine which layer owns the exact field:

- Campus title and description may be synchronized from HubSpot through n8n and the campus SEO template.
- Page-owned metadata may live in Yoast post fields.
- Canonical and indexability may come from WordPress status, Yoast, a template, or code.
- Redirects may exist in Yoast, the Redirection plugin, WordPress, WP Engine, Cloudflare, or application code.
- LLM exports and Markdown variants are generated by code or a plugin, not by manually editing their public output.

Do not create two redirects or patch generated files without finding the generator.

## Page publishing requirements

Every indexable page family must define:

- One canonical URL
- Unique title
- Approved meta description or an explicit exception
- Semantic H1
- Expected index or noindex state
- Sitemap inclusion rule
- Valid structured data when applicable
- Social title, description, and image when required
- Redirect behavior for replaced routes
- Markdown and LLM-export eligibility

Review pages, sandboxes, previews, internal confirmation pages, and replaced routes are noindex or excluded unless an approved requirement says otherwise.

## Redirect procedure

1. Identify the current and intended canonical routes.
2. Search every redirect layer.
3. Record owner, rule, status code, query handling, and chain.
4. Add or change the rule in the authoritative layer only.
5. Verify the source URL logged out, the final URL, one-hop behavior, status, canonical, sitemap, and LLM-export result.
6. Check application, form, UTM, and campus parameters before normalizing query strings.

Redirect chains, loops, and duplicate rules fail verification.

## Markdown pages

Public `.md` variants are generated representations of canonical page content. They must:

- Return `text/markdown`
- Identify the canonical page
- Include the approved visible information needed by an LLM
- Exclude hidden placeholders, scripts, navigation noise, private drafts, and noindex content
- Refresh when the canonical page changes
- Preserve source attribution for claims where the generator supports it

The generator, cache, and invalidation owner still require inventory confirmation.

## `llms.txt` and `llms-full.txt`

The exports must include only eligible canonical public content.

Exclude:

- Redirected legacy URLs
- Noindex pages
- Drafts and previews
- Review and sandbox pages
- Confirmation pages without approved informational value
- Duplicate URL variants
- Pages blocked by legal or privacy policy

The September 17 audit found redirected application routes and the noindex `fall-2025-academic-talk-review` page in `llms.txt`. Treat this as a filtering and route-governance defect, not a manual file-edit request.

Verification requires generator configuration, source page set, generation time, cache state, output URLs, duplicate detection, and spot checks against canonical pages.

## Alpha Answers

Alpha Answers should expose one canonical entry for a grouped answer experience when the approved content model calls for several internal pages or sections. The public index should not create several indistinguishable top-level entries for one conversation.

Before automated import or restructuring, the registry must define:

- Airtable source and approved status
- Stable answer or collection ID
- Public question and answer title
- Canonical public entry
- Internal sequence and navigation
- Video and transcript relationships
- Schema and metadata
- Sitemap, Markdown, and LLM-export eligibility
- Import validation and rollback

The live site contained about 88 Alpha Answers resources during the audit. Exact schema and grouping rules remain incomplete and should fail closed for unattended structural changes.

## Verification

For an SEO or LLM publishing change, check:

- Browser and Googlebot HTTP parity
- Canonical tag
- Title and meta description
- Semantic H1
- Indexability
- Sitemap presence or intended exclusion
- JSON-LD validity
- Redirect result and chain length
- Social metadata when applicable
- Markdown output
- `llms.txt` and `llms-full.txt` inclusion or exclusion
- Duplicate title and canonical reports

Public reachability alone is not enough.
