# Tests and checkers

Agent-independent scripts. Plain Node 20+, no dependencies. Run the repository checks with `npm test` or the detailed validator with `npm run validate`.

- `search-apex-tickets.mjs --url <canonical> [--text <term>] [--check <id>]`: read-only duplicate search over active APEX website tickets. Add `--file <export.json>` for an offline search.

- `validate-ticket.mjs --file <apex tasks json> [--summary]`: protocol step 1. Classifies APEX website tickets against `spec/ticket-classes.json`, reports which inputs are missing, and writes the Missing Info text.
- `page-check.mjs --url <canonical url> [--url ...] [--state Open|Announced] [--json out.json] [--playwright <dir>] [--skip-rendered]`: protocol step 5, ring 2 (text, structure, and framing). Header template and its stylesheet, footer, H1, hero CTAs, intro section, canonical tag, state rules (no launch-era words on Open pages; a named month or season and year on Announced pages), sister-brand words, other-campus image names, approved intro media, CTA link resolution, and `edge-cache-current`. Scans page-owned content only, so shared navigation and footer do not count against a page. Then one rendered check, `team-photo-framing`, in Playwright (borrowed like `rendered-controls.mjs`; `--playwright <dir>` or `PLAYWRIGHT_ROOT`) on desktop 1440x1000 and mobile 390x844: every team-card image (leadership row and carousel slides, lazy loading forced eager, looped duplicates skipped) is measured against its `object-fit: cover` box and the check fails when less than 95% of the image height is visible or more than 30% is cut from either side, naming each failing card with coverage, natural size, box size, and the cropped edges (`viewports.<name>.cards[]` in the JSON has every card). A second rendered check, `brand-visual` (`tests/brand-visual.mjs`, `spec/brand-visual.json`), reads every visible text element's computed font-family, colour and effective solid background on desktop and reports, with selector, value and rule: text not in Montserrat (icon fonts skipped; HubSpot embeds, the Alpha HubSpot Events cards, chat and consent widgets allowlisted and listed as INFO with the reason), a never-row contrast pair from the brand guide's table (sky blue on white or near-white, white on sky blue, white on light blue at body size, navy on medium blue), off-palette large fields and H1-H3 colours once per colour (INFO), and every logo image with the served file's sha256 against `playbook/brand/assets` (INFO). Advisory on the first version: fail-severity findings make the row `warn`, printed and not counted in the exit code, until `check.enforcement.mode` in the spec is `enforced`; severities per finding kind are in the spec. Without Playwright either check is `skipped` with the reason, never passed; `--skip-rendered` skips them on purpose for ring 3 header and footer runs. Exit code 1 on any failure. Screenshots are still required by the protocol and are not produced by this script.
- `validate-community-routing.mjs [--live-map]`: validates the Community routing spec, the partial campus identity crosswalk, canonical URLs, lifecycle mapping, and dated inventory. It is offline by default. `--live-map` adds a read-only comparison with the public growth map and never changes the map or Community app.
- `section-shot.mjs --url <page> --selector <css> [--slide-containing "<text>"] [--name <section>] [--out <dir>] [--viewports desktop,mobile] [--json out.json] [--timeout <ms>] [--playwright <dir>]`: protocol step 5 ring 2 and step 7, the section pair. `--slide-containing "Jason Tan"` (alias `--scroll-to-text`) picks, among the selector's matches, the one whose text contains the string, and when it sits in a Swiper carousel calls `slideTo` on its index first, so `--selector "#team_carousel .swiper-slide" --slide-containing "<person>"` captures a card past the visible slides on screen. Loads the page in Playwright (borrowed the way `rendered-controls.mjs` borrows it), scrolls the element into view, forces its lazy images to load and awaits `img.decode()` on each (bounded, 15 s default), then screenshots the element plus a 16 px margin at deviceScaleFactor 2 on desktop (1440x1000) and mobile (390x844), writing `<slug>-desktop.png` and `<slug>-mobile.png` (slug of `--name`, default the selector). Exit 0 when every image decoded; 1 `IMAGES_NOT_DECODED` (captures still written, each undecoded image named); 2 `SELECTOR_NOT_FOUND`, `NAV_FAILED`, `BAD_URL`, `PLAYWRIGHT_NOT_FOUND`. Attach the pair with `agent/attach-evidence.mjs --section "<name>"`.
- Ring 3 (shared templates): run `page-check.mjs` on two untouched campus pages after any site-wide action and confirm `header-stylesheet-linked` and `footer-template-present` pass.

`build-checks.mjs [--check] [--observer-source <aeo src/checks.mjs>]` compiles `spec/check-rows.json` into `spec/check-bundle.generated.json` (QC loop redesign 2026-09-24, workstream 1): one row per observer check with page family, lifecycle states, element, expected literal or derivation, comparator and threshold, severity, enforced or advisory, ticket or loop-health channel, ticket class and owner role (from the policy bundle), dedupe scope, clear-after runs, grace period, consecutive-run requirement, evidence profile (from the class) and source-health dependencies; plus `retired[]`. It fails closed on an unknown ticket class, role, page family, element, source or requirement reference, on a check that is both a row and retired, and on any name in `registry/observer-checks.json` with neither. Since bundle 1.2 (2026-09-25) every row also carries `grounding` (`complaint`, `source-contract`, `exemplar`, `decision` or `none`, with a reference the builder checks for a real file when it names one) and `depth` (`render` or `http`, filled from `depthDefaults` by page family when the row leaves it out; a row with viewports, a browser dependency or a rendered comparator must be `render`); the builder sets `status: advisory` with `advisoryReason` on any enforced row whose grounding is `none` (promotion rule), and a row may take `channel: source-digest` (a source-versus-source comparison; the builder refuses one that names a WordPress element, whose class fixes through `wordpress-alpha-mcp`, or whose owner role is not in `sourceDigest.ownerRoles`, and refuses `channel: ticket` on any `map-source` row). `--check` exits 1 when the committed bundle is stale; `--observer-source` re-extracts the check names from a local aeo checkout (finding literals, the presentCheck/destinationCheck and check tables, and `const check = "name"` bindings) and fails when the registry is stale; a retired name the observer no longer emits may stay in the registry, since older packets still carry it. `npm run validate` runs the same build, validates the bundle against `spec/schemas/check-bundle.schema.json`, and checks `spec/release-manifest.json` `checkBundleSha256`. Run it (`npm run build:checks`) after any change to `spec/check-rows.json`, the policy bundle, or a registry the rows cite, then put the new `sha256` in the release manifest.

`validate-playbook.mjs` parses every JSON file, validates core source, actor and page-family records, checks ticket-to-recipe references, checks protocol version alignment, and fails on stale entry-point markers. Since 2026-09-24 it also validates `registry/campus-cta-exceptions.json` against its schema (and, through the check-bundle build, every entry's campus slug, CTA, rule and expiry, the leadership groups' slugs and names, and every dedupe alias's check name and pattern) and holds the decision record to one rule: every `docs/decisions.md` row dated 2026-09-24 or later whose Decision column starts with "Decided" must cite at least one `spec/` or `registry/` path in its Applied column (`validateDecisionRows`), so a decision is a playbook change, not prose. `.github/workflows/validate-playbook.yml` runs it on pull requests and main.

Still planned: full JSON Schema documents, a renderer that compares every prose requirement with its machine row, and complete observer-to-page-family coverage.

## agent/ticket-templates.mjs and render-templates-examples.mjs (one place for note wording)

Every note and body the protocol prescribes is a named template in `spec/ticket-templates.json` (schema `spec/schemas/ticket-templates.schema.json`): ordered lines with `{placeholder}` fields, a `required` list, the protocol section it comes from, and an `example`. `agent/ticket-templates.mjs` exports `loadTemplates()`, `renderTemplate(name, fields)` (throws `TemplateError` code `MISSING_FIELD` naming the field; `UNKNOWN_TEMPLATE` for a bad name), `renderTitle(name, fields)` for the two ticket templates with a title line, `templateMarker('triage')`, `closingNoteLines()` (the four lines every closing note starts with), `reviewLine()`, and `assertNoteShape(text)` (closing lines first, review line last, no em dash; `TemplateError` code `NOTE_SHAPE`). Placeholders: `{name}` must be supplied (arrays join with ", "); `{?name|text}` and `{?name|text|else}` render conditionally and may nest; a line may be `{when, text}` or `{each, text}` (per array item, with `{index}` and the item's fields, `{item}` for a string).

Renderers that read it: `render-ticket.mjs` (`triageBody`), `triage-ticket.mjs` (the marker), `validate-ticket.mjs` (`missingInfo`), `diagnose-field.mjs` (`hubspotData`, `syncMapping` title), `agent/intake-policy.mjs` (`intakeClarification`, `ownerUnregistered`, `ownerAmbiguous`, `duplicate`, and `escalationNote` rendering `blocked` for `agent/intake.mjs`), `agent/file-observer-findings.mjs` (`observerBody`, `escalation`, `verified`). `render-templates-examples.mjs` renders every template's example: `--check` (run by `npm run validate`) fails when a block quoted under "Rendered from `spec/ticket-templates.json` template `<name>`" in the protocol or the sweep runbook differs from the renderer or a template is quoted nowhere; `--write` rewrites the quoted blocks. Change wording in the spec, run `--write`, commit both.

```bash
node tests/render-templates-examples.mjs            # print every example
node tests/render-templates-examples.mjs --write    # refresh the quoted blocks in the protocol and runbook
node -e "import('./agent/ticket-templates.mjs').then((m) => console.log(m.renderTemplate('filedLine', { id: 'cmx1', defect: 'a broken packet link' })))"
```

```bash

```

## telemetry-report.mjs (what the agent did, how precise the observer was)

Read-only markdown report from WordPress receipts (`list_receipts`) and APEX website-family Requests. Since the QC loop redesign plan (2026-09-24, workstreams 4 and 8) it also reports observer precision for the tickets filed in the window, for the whole period, per observer run (`customFields.runId`, or the filer's `filerRunId`) and per observer check (`customFields.check`, or the filer's `observerCheck`): precision is the share of observer tickets (`customFields.source` alpha-site-qc, or agent-found with a non-empty `filerRunId`, the filer's own) that ended in a site change (an applied `apply-`, `upload-`, `set-`, `create-`, `delete-`, `restore-` or `update-` receipt carrying the ticket id; prepare, regenerate, flush and purge do not count), a source change (a `SOURCE FIX` or `AUDIT` line on the ticket), or a recorded decision (Blocked with `DECISION NEEDED`, or `customFields.resolutionKind` blocked-decision). The false-positive, fixed-elsewhere, aged-out and retired-or-cleared counts read `customFields.resolutionKind` (backfilled on the 180 sweep tickets on 2026-09-24; written by the filer from workstream 6 on). Median days open counts closed tickets to `completedAt` and open tickets to the report time. `--tickets-file` and `--receipts-file` replace the APEX and WordPress reads for an offline run; tests use `tests/fixtures/telemetry/`.

```bash
node tests/telemetry-report.mjs --since 2026-08-25 --until 2026-09-24T23:59:59Z --label pre-redesign --out docs/telemetry/2026-09-24-observer-precision.md
node tests/telemetry-report.mjs --since 2026-09-15 --tickets-file tickets.json --receipts-file receipts.json --out /tmp/report.md
```

## agent/queue-aging.mjs (the clock on Blocked and Missing Info)

## agent/intake.mjs (the intake agent)

Runs on top of the APEX API as an administrative gatekeeper, not a website executor. For every new or revised website-family ticket it reads the compiled policy, classifies the request, separates requester-owned inputs from derivable and system-owned inputs, applies the policy guard, and resolves one exact owner. Missing requester inputs become typed APEX clarification requirements assigned to the requester. Canonical page URLs and authoritative source values are never requested merely because they were absent from the prose brief. Requester revisions, verified assets, and human comments change the input fingerprint and trigger re-evaluation; intake-authored fields and comments do not.

Complete tickets either enter the scheduled execution queue or route to a human/system owner. The execution queue is limited to the operations explicitly listed in `spec/release-manifest.json`; an Alpha MCP tool existing is not enough. Before an execution-ready ticket is released, intake runs `tests/check-release.mjs` and refuses that handoff unless the compiled policy, production plugin health, and release manifest agree. This gate does not block unrelated clarification or human routing. Ambiguous or unregistered owners, policy exceptions, unknown classes, and exact duplicate candidates fail closed for review. Intake preserves the original description and never edits WordPress, HubSpot, n8n, or another delivery system.

Every observer ticket is administered (QC loop redesign plan workstream 3, 2026-09-24). The website family is the APEX website request family, the "Website" title prefix, the Website and Website QC request types, any ticket filed by the observer or an agent (`customFields.source`), an observer check id, or the observer's title shape; the ticket URL is not a family test, so findings whose URL is a HubSpot event record, the observer workflow, events.alpha.school, the Operations sheet, or a sister site are selected too. Their page is derived by the policy (`customFields.pageUrl`, then the program's page in `registry/campus-pages.json`, then the ticket URL, then the campus named in the title) and is null when there is none; a class that needs a page then goes to `needs-derivation`, never dropped. Classification reads the observer's own check name first (`customFields.check` against each class's `observerChecks`, one class per check; `tests/build-policy.mjs` refuses an overlap), then the recorded `checkId` class, the loop, and the title and detail patterns; a class with `match.urlPattern` matches only tickets whose URL fits it. So a rendered-page timeout, a page 5xx, or an images-failed finding on a page URL is `observer-page-transient` (website agent verifies with two renders), the same title on the workflow URL is `observer-health` (observer owner), and `observer-layout` is the layout checks only.

`--ticket id,id` never drops an id silently: `summary.requestedTickets.dropped` names every requested id that was not administered and why (not in the queue or `--file` input, status outside `--status`, outside the family, `--page`, `--since`, `--limit`), each also printed to stderr; in API mode an id the paged listing missed is read directly and administered when its status is in the queue. Protocol 1d runs inside intake: when the owner role has no registered person (or several and no primary), the route stays as decided and the ticket is Blocked on the website agent operator (Matt Barge, `registry/people.json`) with a note naming the role, the system, and the change (`result.escalation`, `summary.escalated`). Protocol 1c: a ticket carrying an `OPERATOR INSTRUCTION` or `CORRECTION` line is reported (`result.operatorInstruction`) and never re-routed, re-blocked, or re-assigned. A ticket the observer filer created is skipped with reason `observer_filer_owned` (next paragraph). Acceptance fixture: `tests/fixtures/observer-sweep-2026-09-24/` (the 180 observer tickets of the 2026-09-24 sweep, minimal shapes) replays to 180 selected, 180 classified, every one with a person.

Observer filer tickets (2026-09-25). A ticket the observer filer created, `agent/intake-policy.mjs observerFilerOwned` (`customFields.filedBy` is `agent/file-observer-findings.mjs`, or `customFields.filerRunId` is a non-blank string), is never administered by intake at any status, NOT_STARTED included: no clarification request, no owner re-route, no reconcile, no requester notice, in dry run and apply alike; the evaluation is still reported, `result.action` is `no-action` with reason `observer_filer_owned`, and `summary.observerFilerOwned` lists the ids (that morning intake had moved six filer tickets to Missing Info addressed to the observer owner). The filer opens, holds and closes those tickets when their check clears. APEX's own 409 `OBSERVER_FILER_OWNED` on `POST /api/agent/tasks/{id}/reconcile` (PR 409; `agent/apex-errors.mjs` `isFilerOwnedConflict`, the one predicate intake and the filer share: top-level `code`, nested `error.code`, or the message text) is the same skip when APEX decides it first: no error, no retry, no v1 fallback.

Writes use a two-phase marker: `intakePendingHash` is stored before the typed APEX action, and `intakeHash` is finalized only after that action succeeds and the ticket input fingerprint is still current. A failed or concurrent action therefore retries instead of being skipped. Scheduled by `.github/workflows/intake-agent.yml` every ten minutes, dry-run unless the repository variable `INTAKE_APPLY` is `true`; each run scans a 24-hour revision window and uploads its report as an artifact.

```bash
node agent/intake.mjs --file tickets.json --replay --report replay.json     # score a saved set, no writes
node agent/intake.mjs --since 2026-09-17T00:00:00Z --report out.json         # read-only dry-run against APEX
node agent/intake.mjs --since 2026-09-17T00:00:00Z --apply                   # administer APEX only
```

Rollout: keep `INTAKE_APPLY` false; replay the open queue read-only; review missing-info, owner, duplicate, and execution-eligibility deltas; then run one explicitly dispatched APEX-only canary batch reviewed by Matt and Yash. Enable scheduled apply only after the canaries and owner-registry gaps are accepted.

## agent/attach-evidence.mjs (screenshots onto the ticket)

Attaches a desktop and mobile pair to the APEX ticket through `POST /api/agent/tasks/{id}/evidence/screenshots` with the operator key (`APEX_API_TOKEN`, `APEX_API_BASE` derived as intake derives them): the `tests/section-shot.mjs` crop of the element Look for names with `--section "<name>"` (1 to 80 characters, the label the reviewer reads above the thumbnail), and the full-page `tests/rendered-controls.mjs --screenshots <dir>` pair without it; one invocation per pair, same run id. Each file is hashed and posted with the viewport, page URL, run id, capture time, and section when given; APEX verifies the hash, stores the bytes on the ticket, posts the agent comment, logs who attached what and when, and shows the run in the ticket panel's Evidence section with the section crops first. Idempotent per (ticket, viewport, sha256), so the section pair and the full-page pair never collide. Fails closed with typed errors (`MISSING_ARG`, `BAD_PAGE_URL`, `MISSING_FILE`, `NOT_IMAGE`, `TOO_LARGE`, `MISSING_TOKEN`, `APEX_ERROR` with the status and body, `NETWORK`) and sends nothing else. Tests use a mocked fetch.

## agent/file-observer-findings.mjs (observer findings into the queue, and out of it)

The playbook's filer for the production observer (QC loop redesign 2026-09-24, workstream 6): the observer measures and writes a packet, the playbook decides what becomes a ticket, to whom, and when it closes. Input is the packet artifact of one run (`manifest.json`, `findings.json`, `incidents.json`, optional `health.json`, `screenshots/<route>-<viewport>.png`; `--run <github run id>` downloads it with `gh run download -R superbuilders/aeo -n alpha-site-packet-<run>` into `tmp/observer-packets/<run>`) and the compiled check bundle (`spec/check-bundle.generated.json`, schema `spec/schemas/check-bundle.schema.json`, workstream 1: one row per observer check and viewport with `requirement`, `channel` ticket or loop-health, `status` enforced or advisory, `dedupeScope` page, template, program, event or site, `ticketClass`, `ownerRole`, `clearAfterRuns`, `gracePeriodHours`, `requireConsecutiveRuns`, `evidenceProfile`, `sourceHealthDependency` resolved through the bundle's `sourceHealth` map, `suppressWhen`, `exemptionsRef`, `decisionPending`; the tests run against `tests/fixtures/observer-filer/check-bundle.generated.json`, a byte copy of the committed bundle that the first test compares by sha256). The open queue is read from the v1 API (a status whose listing hits the 20-page cap is logged and named in the report's `queueWarnings`), or offline from `--queue <export.json>` for a dry run only.

Per finding, in order: a check with no row, or a retired one, is dropped and counted (telemetry); a loop-health row is counted for the observer owner and never enters the queue; a source-digest row (bundle 1.2) is never filed: each finding becomes one audit line (row, record, observed, expected, sources with read time, observer id, decision pending if any) in `source-digest.md` next to the report, grouped by owner role in the bundle's `sourceDigest.ownerRoles` order with the registered person named (or the operator when the role has none), the summary carries `counts.sourceDigest` and `sourceDigest.byOwnerRole`, and a ticket already open on such a row is reported as unresolved and left to its owner; an advisory row is counted and never filed; a finding is suppressed and counted when its row depends on a source that `health.json` (else `manifest.providers`, matched through `sourceHealth[].providerEntity`, stale after `staleAfterHours`) reports degraded, failed or stale, or marks `suppressFindings: true` (not-collected, optional and disabled measured nothing and suppress nothing), when its row's evidence profile names an observer screenshot and the artifact lacks the complete desktop and mobile pair for the route (PR 26), or when the finding carries a `suppressWhen` condition (`event-ended` is derived from the event's end time, the rest from the finding's `conditions`). A packet that repeats an incident id counts it once per scope. Loop-health suppression is the observer's own: it applies the loop-health rows' `suppresses` before the packet is written and reports the count in `health.json` `suppressedByLoopHealth`, which the filer carries as `suppressedByObserver`; the filer no longer expects loop-health items in `findings.json` and suppresses nothing on their account. Holds: when `manifest.checkBundle.status` is `verified` for this bundle's sha256 the observer already applied the grace period and `requireConsecutiveRuns` and the filer does not re-apply them (`holds` in the report says which); otherwise the grace period runs from the incident's first-seen time and `requireConsecutiveRuns` reads the incident's `consecutiveFailingRuns` (aeo PR 24), else this run plus the manifest's `previousRunId` in the incident's run history, never the lifetime `occurrences`. The rest group by dedupe scope into one ticket per scope, keyed `observer:<row key>:<scopeKey>` where the row key is the row id minus its `.desktop`/`.mobile` suffix: the desktop and mobile rows of one requirement merge, rows of different classes or owners on the same scope never do, and while a ticket is open on one key the other rows on that page still file; the page list (template, site) or event list (event) goes in the body. A row whose `decisionPending` ticket is open files nothing new (the group is reported against that ticket); once that ticket is closed the row files again with the decision under Related. Each ticket is rendered to the contract (owner line first, then Claim, Page, Element, Observed, Expected, Source with read time, Defect class, Class, Owner, Fix path, Done when, Evidence, Exemptions, Playbook, History) and checked with `validate-ticket.mjs` `contractCheck`; one that fails is a filer defect and is reported, not filed. Em dashes and the ellipsis character in observer values are rewritten before they reach a title, body or note, and every note the filer writes passes `assertNoteShape`. Dedupe follows `agent/file-found-ticket.mjs`: idempotency key, exact title, then any open ticket carrying one of the group's observer ids or the same check on one of its pages. Class and owner come from the policy bundle; a role with no registered APEX user escalates to the website agent operator as Blocked with the role named in the body (protocol 1d). ## agent/record-decision.mjs (a decision arriving by email becomes a playbook change)

## photo-framing.mjs and agent/frame-headshot.mjs (headshot framing)

`tests/photo-framing.mjs` holds the framing math (`frameCoverage`, `judgeFraming`, `frameForFit`) and the in-page measurement (`measureTeamCardsInPage`) behind `page-check.mjs team-photo-framing`. Coverage is `min(imageRatio, boxRatio) / max(imageRatio, boxRatio)`; the cropped axis is vertical when the image is taller than the box (the head-cutting case) and horizontal when wider; the cut edges follow `object-position`. `object-fit: contain` never crops; `fill` fails when it stretches by more than 5%. The measured card boxes per page are in `spec/team-card-frame.json` (the ratio is per page and viewport, not one site value).
