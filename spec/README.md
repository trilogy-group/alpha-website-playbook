# Spec (machine-readable requirements)

- `campus-lifecycle.json`: campus states as the sources define them, per-campus classification, source conflicts.
- `campus-page-model.json`: section model derived from the live pages.
- `site-rules.json`: site-wide rule ids.
- `community-routing.json`: Community URL contract, authority boundary, lifecycle normalization, exact identity join, and fail-closed behavior; `communityHosts` (canonical `www.community.alpha.school`, apex host redirecting) and the `urlContract.urlForm` decision flag (`?campus=<slug>` recommended vs `/campuses/prog-<id>`, ticket cmu4g45fg).
- `observer-check-map.json`: every production observer check mapped to a coarse requirement id, with status, plus requirements covered by other tools. The compiled row per check is in the check bundle below. `dedupeAliases` (0.6, 2026-09-24): per observer check, the older check ids (`tests/page-check.mjs` `cta-links-resolve`, `cta-hidden-everywhere`, the sweep agents' `campus.resources.calendar-reachable` and the like) and title patterns under which the same defect was filed before the bundle; `agent/file-observer-findings.mjs` treats an open ticket on the same page carrying one as the same ticket.
- `check-rows.json`: the source rows of the check bundle (QC loop redesign 2026-09-24, workstreams 1 and 2): per observer check, the page family and lifecycle states, the element, the expected literal or derivation (source, field, transform), comparator and threshold, severity, enforced or advisory, ticket channel or loop health, ticket class, dedupe scope, clear-after runs, grace period, consecutive-run requirement, source-health dependencies, exemptions and the decision ticket that can change the row; plus `retired[]` with the reason per retired check. Thresholds, host lists, exemptions and grace periods live here and in the registries, never in the observer's config.
  1.2 (2026-09-25, decisions by Matt Barge): `channel` may also be `source-digest`, for a source-versus-source comparison that is not a website defect (the `map-source` rows comparing the Operations sheet, the growth map API and HubSpot Programs with each other: operations row presence, address and lifecycle agreement, campus missing from the map or from Operations, duplicate program records, `hubspot-map-sync`, program facts; and the `site.community.routing.*` rows about the Community record, URL form and host); rows about a WordPress element (a CTA, a link, page copy, an image) stay `ticket`, and the builder refuses a `source-digest` row that names a WordPress element or whose class fixes through the `wordpress-alpha-mcp` path. The filer never files a `source-digest` row: it writes `source-digest.md` next to its report, grouped by the owner roles in `sourceDigest.ownerRoles` (`growth-map-owner`, `hubspot-program-admin`, `operations-sheet-owner`, `community-app-owner`) with the audit line per finding, and its summary prints the count; tickets already open on those rows are left alone. `grounding` `{kind, ref}` on every row: `complaint`, `source-contract`, `exemplar`, `decision` or `none`, with where it lives (the 2026-09-15 precedence: decision, then source system, then exemplar, then complaint); the builder sets `status: advisory` on any enforced row whose grounding is `none` and says so in `advisoryReason` (the promotion rule, `docs/observer-requirements.md`). `depth` (`render` or `http`) per row, defaulted from `pageFamily` through `depthDefaults` (see the depth contract below).
  1.3 (2026-09-25, decision by Matt Barge: check from HubSpot to the website, not only from the website to HubSpot): `entitySource` per row (`hubspot-programs` or `map`, defaulted from `pageFamily` through the bundle's `entitySources.<id>.pageFamilies`; campus rows enumerate from HubSpot Programs whose `type` is Open or Announced and whose `website` is on alpha.school, take the lifecycle state from `type` and fetch the page at `website` with the trailing slash normalised; the map is downstream). `expected.derive.onMissing` (`finding` or `skip`, default `skip`): on `finding`, an in-scope campus with no entry in the registry the row derives from is a finding of the same row with `missingExpectation: true`, titled "no approved <literals.missingThing> recorded for <state> campus <name>", filed Missing Info to the row's owner role (the registry owner) with `literals.missingAsk` (a row's `literals` are also mirrored at `expected.literal`, where the observer reads them); `equals-approved-media` means the rendered slot's attachment id equals the registry `attachmentId` (a null `openMedia` is a missing expectation, a mismatch names the observed asset), and `literals.launchWords` is the word list for the observer's vision pass over the primary campus visuals. Coverage rows: `site.coverage.open-campus-registries` (`campus-registry-coverage`, one Missing Info per campus and registry gap from `literals.registries`, `dedupeScope: campus-registry`), `site.coverage.program-page` (`program-page-present`: every Open or Announced Program with an alpha.school website has a 200 page naming the campus that the map lists; a missing page is critical, a missing map record is a source-digest line under `hubspot-map-sync`) and `site.coverage.open-campus-rendered` (`campus-page-rendered`, loop health: every Open campus page rendered in the full run). `aliases.pageCheck` maps every `tests/page-check.mjs` check id to its row (`aliases.pageCheckUnmapped` names the rest with the reason) and `agent/file-found-ticket.mjs` writes `customFields.requirementId` from it.
- `observer-comparators.json`: every comparator type a row may use, one line of semantics each, identical to the observer's published list (superbuilders/aeo `alpha-site-system/spec/supported-comparators.json`, 35 types); `tests/build-checks.mjs` refuses a row whose comparator is not listed, the bundle carries the list as `comparators`, and the observer fails loop health on a bundle that names a type outside its list (repair 3); `tests/sync-observer-comparators.mjs` refetches the observer's list and reports drift, and `tests/observer-conformance.test.mjs` asserts the copy from this side (the contract is written up in `docs/observer-requirements.md`, "bundle-versus-observer conformance").
- `check-bundle.generated.json`: generated by `tests/build-checks.mjs` from `check-rows.json`, the policy bundle (ticket class to owner role and evidence profile), the field map, the lifecycle spec and the registries; hashed (`sha256`, carried by `release-manifest.json` as `checkBundleSha256`). The observer loads it and cites the row id and bundle version on every finding; `agent/file-observer-findings.mjs` applies it. Every name in `registry/observer-checks.json` is a row or a retirement, or `npm run validate` fails. Schema: `schemas/check-bundle.schema.json` (the row field names are the contract shared with the observer and the filer).
- `ticket-classes.json`: intake requirements per ticket class. 0.13 (2026-09-25, one id everywhere): a class may carry `matchRequirementIds` (check-row ids) and `matchCheckIds` (page-check and agent-found ids); `agent/intake-policy.mjs` and `agent/file-found-ticket.mjs` classify on them before the observer check name and before any title pattern, and `tests/build-policy.mjs` refuses an id claimed by two classes. `intake-policy.json` 1.2: an owner rule may match on `checkIds` or `requirementIds`, and a derivable field may name `missingRegistryOwnerRole`, so a registry with no entry for the campus is Missing Info to that owner (outcome `missing-registry`), never `needs-derivation` to internal triage.

### Depth contract (check bundle 1.2, 2026-09-25)

Every row carries `depth`, which tells the observer how to read the page for that row:

- `render`: load the route in a browser on desktop 1440x1000 and mobile 390x844, wait for fonts and images, take the screenshot pair, then measure. Campus pages (`campus`, `campus-open`, `campus-announced`, `campus-pre-announcement`), the homepage, Locations and the events pages, and the pseudo-families that group them (`map-routes`, `critical-routes`) default to `render`.
- `http`: one HTTP fetch of the route (status, headers, body) with no rendering; for the `map-source` pseudo-family a source read and no fetch at all. The long tail (`site`: every public route) and every other family default to `http`.

The bundle's `depthDefaults` lists the families under each depth (`pageFamilies.$depthNote` in `check-rows.json` is the prose). A row may set `depth` itself; the builder fills it from the family when the row leaves it out, and refuses `http` on a row with `viewports`, a `browser` source-health dependency, a `*-rendered` comparator or an `observer.browser` element. The observer renders a route once per run when any row on it is `render`, and never renders a route whose rows are all `http`; a render-only finding (layout, crop, header overlap, images, screenshots) on an `http` row is a bundle defect, not a page defect. Cadence: full render runs twice a day (06:00 and 21:00 UTC), events every two hours, source contracts daily at 06:30 UTC into the source digest (`docs/sweep-runbook.md`, Cadence, breadth and depth).
- `inventory/`: raw per-page and cross-system routing inventories (dated).
- `campus-page-requirements.json`: per-state and per-section campus requirements; observed baselines are labeled separately from active source-backed rules.
- `source-authority.json`: authoritative system, delivery path, owner and verification method by website field family.
- `actor-capabilities.json`: what each human or agent actor can actually execute, separate from the Alpha MCP tool inventory.
- `page-family-requirements.json`: coverage and readiness status for campus and non-campus page families.
- `brand-visual.json`: the official Alpha visual brand for the website (palette with roles, gradients, contrast table with verdicts, Montserrat type scale, logo rules and canonical file hashes, approved claims cross-referenced to MacKenzie's copy rules, provenance: canon vs skill extension) and the configuration of the `page-check brand-visual` check (severities, enforcement mode, font allowlist). Schema-validated; the logo files in `playbook/brand/assets/` must match the recorded hashes.
- `requester-notices.json`: the review gate for requester notices (mode all or flagged, the reviewer, the send and hold reactions, expiry, internal domains, the flag rules, the ledger location); read by `agent/notice-review.mjs`, validated by `tests/validate-playbook.mjs`.
- `ticket-templates.json`: the wording and line order of every note and body the ticket protocol prescribes (closing note `resolution` and `verified`, `missingInfo`, intake's `intakeClarification`, `blocked` with DECISION NEEDED and the 1d `escalation`, `ownerUnregistered`, `ownerAmbiguous`, `duplicate`, `filedLine`, `claimed`, the contract bodies `triageBody` and `observerBody`, the source-side tickets `hubspotData` and `syncMapping`), each with ordered lines, `{placeholder}` fields, a `required` list, a `protocolSection` and an `example`; plus the triage marker and the `rules` block (requester text first, the four closing lines, the review line, no em dashes, status means one thing). Rendered by `agent/ticket-templates.mjs`; quoted in the protocol through `tests/render-templates-examples.mjs`.
- `schemas/`: JSON Schemas enforced by `tests/validate-playbook.mjs` for the authority, capability, page-family, brand-visual and ticket-template specs and the check bundle.
