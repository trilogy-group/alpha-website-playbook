# Spec (machine-readable requirements)

- `campus-lifecycle.json`: campus states as the sources define them, per-campus classification, source conflicts.
- `campus-page-model.json`: section model derived from the live pages.
- `site-rules.json`: site-wide rule ids.
- `community-routing.json`: Community URL contract, authority boundary, lifecycle normalization, exact identity join, and fail-closed behavior; `communityHosts` (canonical `www.community.alpha.school`, apex host redirecting) and the `urlContract.urlForm` decision flag (`?campus=<slug>` recommended vs `/campuses/prog-<id>`, ticket cmu4g45fg).
- `observer-check-map.json`: every production observer check mapped to a coarse requirement id, with status, plus requirements covered by other tools. The compiled row per check is in the check bundle below.
- `check-rows.json`: the source rows of the check bundle (QC loop redesign 2026-09-24, workstreams 1 and 2): per observer check, the page family and lifecycle states, the element, the expected literal or derivation (source, field, transform), comparator and threshold, severity, enforced or advisory, ticket channel or loop health, ticket class, dedupe scope, clear-after runs, grace period, consecutive-run requirement, source-health dependencies, exemptions and the decision ticket that can change the row; plus `retired[]` with the reason per retired check. Thresholds, host lists, exemptions and grace periods live here and in the registries, never in the observer's config.
- `check-bundle.generated.json`: generated by `tests/build-checks.mjs` from `check-rows.json`, the policy bundle (ticket class to owner role and evidence profile), the field map, the lifecycle spec and the registries; hashed (`sha256`, carried by `release-manifest.json` as `checkBundleSha256`). The observer loads it and cites the row id and bundle version on every finding; `agent/file-observer-findings.mjs` applies it. Every name in `registry/observer-checks.json` is a row or a retirement, or `npm run validate` fails. Schema: `schemas/check-bundle.schema.json` (the row field names are the contract shared with the observer and the filer).
- `ticket-classes.json`: intake requirements per ticket class.
- `inventory/`: raw per-page and cross-system routing inventories (dated).
- `campus-page-requirements.json`: per-state and per-section campus requirements; observed baselines are labeled separately from active source-backed rules.
- `source-authority.json`: authoritative system, delivery path, owner and verification method by website field family.
- `actor-capabilities.json`: what each human or agent actor can actually execute, separate from the Alpha MCP tool inventory.
- `page-family-requirements.json`: coverage and readiness status for campus and non-campus page families.
- `brand-visual.json`: the official Alpha visual brand for the website (palette with roles, gradients, contrast table with verdicts, Montserrat type scale, logo rules and canonical file hashes, approved claims cross-referenced to MacKenzie's copy rules, provenance: canon vs skill extension) and the configuration of the `page-check brand-visual` check (severities, enforcement mode, font allowlist). Schema-validated; the logo files in `playbook/brand/assets/` must match the recorded hashes.
- `requester-notices.json`: the review gate for requester notices (mode all or flagged, the reviewer, the send and hold reactions, expiry, internal domains, the flag rules, the ledger location); read by `agent/notice-review.mjs`, validated by `tests/validate-playbook.mjs`.
- `schemas/`: JSON Schemas enforced by `tests/validate-playbook.mjs` for the authority, capability, page-family and brand-visual specs and the check bundle.
